# Сводка родительского чата — бот

Telegram-бот, который читает родительские чаты в MAX и раз в сутки присылает выжимку:
что нужно сделать, сколько сдать денег, какие даты и до чего договорились.
Чатов может быть несколько — по каждому приходит своя сводка.

В отличие от [личной версии](../Max_connect), здесь всё делается внутри Telegram:
человек присылает код приглашения, номер телефона и код из SMS — и дальше сервис
работает сам. Ни GitHub, ни терминал пользователю не нужны.

Проект открытый, лицензия MIT — поднимайте свой экземпляр, дорабатывайте, делитесь.

## Состояние

Работает: онбординг целиком, несколько чатов на пользователя, ежедневные сводки
по каждому чату отдельно, утреннее напоминание о планах на день, внеочередная
сводка при всплеске активности, сводка и вопросы по запросу, приглашения ссылкой,
кнопочное меню, внятные сообщения о сбоях. Проверено на живом чате.

Не сделано: чтение содержимого картинок — сейчас бот помечает, что фото было,
и советует посмотреть в чате. Дальнейшее — в [ROADMAP.md](ROADMAP.md).

## Как устроено

```
Один процесс на сервере:
  ├─ aiogram — бот: онбординг и команды, один на всех пользователей
  ├─ PyMax   — вход в MAX и чтение истории, сессия на каждого
  ├─ планировщик — вечерняя сводка, утреннее напоминание, слежение за всплесками
  └─ SQLite  — пользователи, их чаты, планы на завтра, замеры активности, события
       └─► Kimi (или GigaChat) ─► сводка ─► в личку пользователю
```

Почему постоянный процесс, а не serverless: вход в MAX — это диалог на несколько
минут (номер → код из SMS → пароль), и всё это время соединение с MAX должно быть живо.

## Онбординг глазами пользователя

1. `/start` → бот просит код приглашения
2. Объясняет, какой доступ получает, и просит включить в MAX пароль для входа —
   без него MAX не пускает на новое устройство и шлёт коды в мобильное приложение
3. Номер телефона → код из SMS → пароль от MAX
4. Выбор чатов кнопками из списка групп — можно отметить несколько
5. Выбор времени сводки
6. Дальше молчит: вечером присылает выжимку по каждому чату, утром — короткое
   напоминание о том, что запланировано на день

## Команды

| Команда | Кому | Что делает |
|---|---|---|
| `/start` | всем | подключение или справка |
| `/summary`, `/summary 3` | пользователю | сводка за сутки или за N дней |
| `/q вопрос` | пользователю | ответ по переписке за месяц |
| `/settings` | пользователю | список чатов, время сводки, утреннее напоминание, пауза |
| `/stop` | пользователю | удалить сессию и все данные |
| `/invite` | админу | выдать код приглашения |
| `/users` | админу | список подключённых |
| `/provider all kimi` | админу | переключить модель всем или одному |
| `/health` | админу | у кого что сломалось |

## Запуск

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
cp .env.example .env    # заполнить
set -a && source .env && set +a
./.venv/bin/python -m app.main
```

На сервере — через systemd, чтобы процесс поднимался после перезагрузки.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `ADMIN_IDS` | telegram id админов через запятую |
| `SECRET_KEY` | ключ шифрования сессий MAX. **Потеряете — все подключения придётся делать заново** |
| `LLM_PROVIDER` | `kimi` (по умолчанию) или `gigachat` |
| `KIMI_API_KEY`, `KIMI_MODEL` | доступ к Kimi |
| `GIGACHAT_AUTH_KEY` | запасной провайдер |
| `TIMEZONE`, `DEFAULT_DIGEST_TIME` | по умолчанию Москва и 20:00 |
| `DEFAULT_MORNING_TIME` | утреннее напоминание, по умолчанию 07:30 |
| `DATA_DIR` | где лежат база и сессии, по умолчанию `data/` |
| `BURST_ENABLED` | слежение за всплесками, по умолчанию включено |
| `BURST_MIN_MESSAGES`, `BURST_FACTOR` | пороги всплеска: 25 сообщений за час и вчетверо больше обычного |
| `BURST_COOLDOWN_HOURS`, `QUIET_HOURS` | пауза после срабатывания (6 ч) и тихие часы (`23-8`) |

## Всплески активности

Раз в час бот считает, сколько сообщений пришло в чат, и сравнивает с обычным для
этого чата. Если сообщений разом стало вчетверо больше обычного и при этом не меньше
двадцати пяти — присылает сводку, не дожидаясь вечера. Модель для самого замера
не нужна, это просто счёт сообщений.

Пороги нарочно высокие, а после срабатывания бот молчит шесть часов и не тревожит
ночью: сервис, который шлёт лишнее, выключают быстрее, чем тот, который иногда
опаздывает. Первые сутки работы порог только абсолютный — сравнивать ещё не с чем.
Выключается кнопкой в `/settings`.

## Про данные и доверие

Сервис хранит **сессии чужих аккаунтов MAX**. Такая сессия — это доступ к мессенджеру
целиком, а не к одному чату. Отсюда решения в коде:

- сессии лежат на диске зашифрованными (`app/crypto.py`), расшифровываются во временный
  каталог только на время работы с MAX и стираются после;
- `/stop` действительно удаляет сессию и запись пользователя;
- на первом экране бот прямо говорит, какой доступ получает и куда уходят тексты;
- вход только по приглашению — посторонние не могут отдать свои аккаунты.

Тексты сообщений уходят в языковую модель. У Kimi это Moonshot (Китай), у GigaChat —
Сбер (Россия). В родительских чатах бывают имена детей и телефоны родителей —
пользователи должны это понимать, поэтому в промпте стоит запрет тащить
персональные контакты в сводку.

## Ответственность

Сервис работает через **неофициальный внутренний API MAX** (библиотека PyMax). Это
не запрещено технически, но формально нарушает условия использования мессенджера,
и MAX вправе ограничить или заблокировать аккаунт. Документированные причины
блокировок связаны с рассылками и спамом — режим «только чтение», в котором работает
бот, у самого MAX отнесён к минимальному риску, но гарантий никто не даёт.

Поднимая свой экземпляр, вы становитесь оператором чужих данных: у вас на диске
оказываются сессии MAX ваших пользователей, то есть доступ к их мессенджерам целиком.
Скажите им об этом прямо — в текстах бота это уже сделано, не убирайте.

## Ограничения

- PyMax работает через неофициальный внутренний API MAX: он может измениться,
  и формально это нарушает условия сервиса.
- Читается только текст. Опросы разбираются целиком, у файлов видно имя,
  а вот содержимое фотографий бот не знает — только сообщает, что картинка была.
- Несколько аккаунтов с одного адреса — заметный для MAX паттерн. Сводки разнесены
  по времени, между запросами паузы, но риск блокировки аккаунта ненулевой.
